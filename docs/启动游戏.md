# 启动游戏 · 流程与判据（start_game.json）

> 对应脚本：`assets/resource/pipeline/start_game.json`（25 节点）
> 最后更新：2026-11-12（v10）

## 一、整体结构

一个**调度器 + 处理器**模型：

- `启动_守卫`：`DirectHit` + `DoNothing`，`post_delay 100`、`max_hit 60`，`next` 是一张**候选表**，末尾指回自己 → 等价于“每 0.1 秒扫一遍全屏，谁在就处理谁”。
- 每个处理器命中后做完自己的动作，`next` 统一回 `启动_守卫`。
- 终点：`大厅_确认_探测` 命中后 → `大厅_完成`（`next: []`）→ 任务 `succeeded`。
- 兜底：`停滞计时_1/2/3`（各 45 秒）→ `停滞重启`（StopApp）→ `重启_拉起`（StartApp）→ 回守卫；三次都不行 → `failed`。

## 三、大厅三级确认

| 顺序 | 节点 | 判据 |
|---|---|---|
| 1 | `大厅_已进入` | 底栏六项任一 |
| 2 | `大厅_确认_修正者` | OCR「修正者」`[495,663,90,32]` |
| 3 | `大厅_确认_探测` | OCR「探测」`[600,663,80,32]` |

三项都过才算进大厅，避免“停在某个子页面但底栏碰巧露出”的误判。

## 四、关键坑位（都踩过）

### 1. 「签到中心」四页签轮播页（2026-11-12）

登录后必现的全屏页：面板 x 278–1196 / y 95–625，左侧四页签（每日签到 y108 / 恒定观测 y191 / 七日签到 y272 / 百宝囊 y354），**每 30–50 秒自动轮播一格**，面板外是不透明黑遮罩，**没有任何关闭按钮**。

- ❌ 点面板外无效（黑遮罩不吃点击）
- ❌ 用页签文字判“当前在哪页”不稳定（会轮播）
- ✅ 用 **OR 四词 + ROI 只框页签栏** 判“是不是这个面板”
- ✅ **点 (462,16) 关闭**（= MuMu 空格键，与画面内容无关）

### 2. 「空白」是键盘键位，不是触摸坐标

`(462,16)` 落在 MuMu 空格键热区，作用是“按一下空格”。所以：

- 不要问“这个坐标点下去会不会点到东西”；
- 要问“这个界面收不收空格键”。

### 3. 识别节点必须带 `action`

`recognition` 命中却没有 `action` 时，节点什么也不做，只消耗 `max_hit`——11-12 那次 `弹窗_每日签到` 就是这样空转 3 次。

### 4. 侧边菜单会挡住大厅判据

关掉签到中心后浮出的抽屉（正在播放 / 钥从 / 管理员 / 图鉴 / 成就 / 弥弥观测站 / 心链事件 / 好友 / 签到 / 公告 / 问卷 / 兑换礼包 / 关注福利 / 设置 / 电源）覆盖右侧 x>845，导致「仓库」「游园街」读不到 → 必须排在 `大厅_已进入` **之前**。

### 5. 不要用「启动_失败」当 DirectHit

曾用 `DirectHit` 让“没进游戏”也能 `Succeeded`（假成功），导致后续任务全部连锁失败。现在它是 OCR（启动失败/网络异常/重试）且不在守卫候选里。
